# 明日方舟干员名字输入器设计规格

日期：2026-07-31
状态：已由主人批准，等待书面规格复核

## 1. 目标

制作一个可嵌入现有网页小游戏的明日方舟干员名字输入器。宿主只需引入一个 JavaScript 文件并放置一个自定义元素，即可获得输入框、自动补全、键盘与触摸操作以及可选的角色选择事件。

首个版本强调以下目标：

- 无运行时 JavaScript 依赖。
- 不要求宿主使用 npm、打包器或特定前端框架。
- 不污染宿主样式，也不被宿主的全局 CSS 意外破坏。
- 搜索数据构建时固化，浏览器搜索不依赖远程 API。
- 数据更新流程可由其他 agent 通过单条命令安全执行。
- 自由文本、简单接入和高级事件接入可以同时成立。

## 2. 范围

### 2.1 包含

- PRTS Wiki 当前收录的国服已实装可玩干员。
- 正式中文名、正式名全拼、正式名拼音首字母。
- 萌娘百科角色条目“基本资料”中的“别号”字段。
- 别号原文、别号全拼、别号拼音首字母。
- 主读音及人工维护的合理备用读音。
- 候选项中的 PRTS 头像和正式中文名。
- 现代桌面与手机浏览器，包括当前 Chrome、Edge、Firefox、Safari 和常见手机 WebView。

### 2.2 不包含

- 剧情 NPC、敌方单位、Boss、博士或其他非可玩干员。
- 职业、星级或其他角色资料展示。
- IE 和非常旧的 WebView。
- 错别字纠正、编辑距离等模糊搜索。
- 运行时角色数据更新。
- 全量头像预取、头像离线打包或头像代理服务。
- 宿主自定义候选列表渲染器。
- 框架专用包装器。

## 3. 总体架构

系统分为构建时数据管线与浏览器运行时组件，两者通过生成的角色快照隔离。

### 3.1 构建时

1. PRTS 数据适配器获取国服已实装可玩干员。
2. 每个干员至少提取 PRTS `sortId`、正式中文名、实装时间和 PRTS 头像 URL。
3. 萌娘百科数据适配器按 PRTS 正式名关联对应角色条目，允许正常重定向。
4. 适配器只读取角色条目基本资料中的“别号”字段，不读取《明日方舟/梗》页面。
5. 拼音处理器为正式名与别号生成主全拼和首字母。
6. 人工覆盖文件补充或修正主读音与备用读音。
7. 校验器检查主数据、数据差异、别号映射和拼音覆盖。
8. 校验通过后原子替换生成快照。
9. 构建器将快照、搜索逻辑和 Web Component 打包进 `arknights-name-input.js`。

### 3.2 浏览器运行时

1. 宿主加载 `arknights-name-input.js`。
2. 脚本注册 `<arknights-name-input>`。
3. 组件在 Shadow DOM 内渲染输入框与候选列表。
4. 用户输入只查询内置索引，不请求 PRTS 或萌娘百科的数据接口。
5. 组件只为当前展示的候选设置 PRTS 头像 URL。
6. 用户选择后，组件写回正式中文名并派发标准 DOM 事件。

浏览器运行时唯一允许的外部网络流量是候选头像加载。萌娘百科不会被宿主浏览器访问。

## 4. 数据模型

生成快照采用带版本号的结构。实现可以为体积压缩内部字段，但构建前的可读数据应表达以下语义：

```json
{
  "schemaVersion": 1,
  "generatedAt": "ISO-8601 timestamp",
  "sources": {
    "prts": "source URL or dataset identifier",
    "moegirl": "source URL or API identifier"
  },
  "operators": [
    {
      "id": "prts:268",
      "name": "重岳",
      "avatarUrl": "https://...",
      "nameSearch": {
        "primaryPinyin": "chongyue",
        "alternatePinyin": ["zhongyue"],
        "primaryInitials": "cy",
        "alternateInitials": ["zy"]
      },
      "aliases": [
        {
          "text": "示例别号",
          "primaryPinyin": "shiliebiehao",
          "alternatePinyin": [],
          "primaryInitials": "slbh",
          "alternateInitials": []
        }
      ]
    }
  ]
}
```

约束：

- `id`、`name` 必须存在且在快照中唯一。
- `id` 使用 `prts:<sortId>` 格式。`sortId` 来自 PRTS“干员一览/干员id”结构化数据，不使用数组位置、显示名哈希或本地抓取顺序。
- 展示用名称和别号保留原文；搜索键另行规范化。
- 同一别号可以属于多个干员，这是合法的一对多关系。
- 拼音覆盖以稳定 ID 为主键，避免正式名变化后修正项静默丢失。

## 5. 数据来源与关联

### 5.1 PRTS

PRTS 是干员主表，决定哪些条目进入快照，并提供 `sortId`、正式中文名、实装时间和头像 URL。

仅选择 `sortId > 0` 且实装时间不晚于更新时上海时间的条目，得到当前国服已实装且可玩的常规干员。`sortId = -1` 的模式专属临时干员和实装时间仍在未来的条目必须排除。若来源不能可靠提供这一筛选结果，更新必须失败，不得自动扩大到 NPC、敌人或未实装角色。

### 5.2 萌娘百科

萌娘百科只提供搜索别号。更新工具使用 PRTS 正式名定位同名角色条目，读取“基本资料 → 别号”。例如，忍冬条目中的“铃兰妈”应成为忍冬的搜索别号。

关联规则：

- 允许站点的正常页面重定向。
- 页面不存在、出现消歧义或没有“别号”字段时记录明确警告。
- 关联失败不阻止该 PRTS 干员进入快照。
- 不从正文、萌点、相关人士或“梗”页面推测别号。
- 不将关联失败静默替换为其他角色页面。

### 5.3 使用与归属说明

README 必须列出数据来源、快照生成时间和相关来源链接。实现阶段应核对并遵守两个站点当时有效的访问、署名和内容使用要求；本规格不假定许可条款永远不变。

## 6. 拼音与文本规范化

搜索前对用户输入和索引键执行相同规范化：

- Unicode NFKC 规范化。
- 拉丁字母转小写。
- 去除首尾空白。
- 搜索键忽略空格和约定的常见分隔符。
- 展示文本不因搜索规范化而改变。

正式名和每个别号分别生成：

- 主全拼。
- 主拼音首字母。
- 人工维护的备用全拼。
- 每个备用全拼对应的首字母。

多音字不自动展开所有排列组合，避免制造大量无意义结果。人工覆盖文件只收录合理变体。例如“重岳”可配置主读音 `chongyue`、备用读音 `zhongyue`，从而支持 `chongyue`、`zhongyue`、`cy` 和 `zy`。

## 7. 搜索与排序

支持三种匹配质量：

1. 精确匹配。
2. 前缀匹配。
3. 包含匹配。

排序先比较匹配质量，再比较字段优先级。相同匹配质量下，字段优先级为：

1. 正式中文名。
2. 正式名主全拼。
3. 正式名备用全拼。
4. 正式名主拼音首字母。
5. 正式名备用拼音首字母。
6. 中文别号。
7. 别号主全拼。
8. 别号备用全拼。
9. 别号主拼音首字母。
10. 别号备用拼音首字母。

这保证正式名首字母命中高于别号首字母命中。例如输入 `ll` 时，正式名首字母为 `ll` 的“铃兰”排在仅因别号首字母为 `ll` 而命中的干员之前。

其他规则：

- 同一干员被多个字段命中时只展示一次，使用其最高分命中解释。
- 同分结果使用稳定 ID 进行确定性排序，保证不同浏览器顺序一致。
- 同一输入对应多个干员时全部保留，直到达到 `maxResults` 展示上限。
- 搜索不自动纠正或替换用户输入。

## 8. Web Component 接口

### 8.1 最小接入

```html
<script src="/arknights-name-input.js"></script>

<arknights-name-input
  placeholder="输入干员名称"
  max-results="8"
></arknights-name-input>
```

脚本重复引入时应检测元素是否已注册，不因重复调用 `customElements.define` 抛出异常。

### 8.2 属性与方法

| HTML 属性 | JavaScript 属性 | 语义 |
| --- | --- | --- |
| `value` | `value` | 当前输入文字，可读写 |
| `placeholder` | `placeholder` | 输入框占位文字 |
| `disabled` | `disabled` | 禁用状态 |
| `max-results` | `maxResults` | 每轮最多展示的候选数量，默认 8 |

只读状态：

- `valid`：当前文字精确等于某个正式中文名时为 `true`。
- `selectedCharacter`：当前精确正式名对应的 `{ id, name, avatarUrl }` 对象，否则为 `null`。

方法：

- `focus()`：聚焦内部输入框。
- `clear()`：清空文字、选择和候选列表。

`maxResults` 必须是正整数。无效值回退到默认值 8，并只输出一次清晰的开发者警告。

与原生表单控件一致，程序直接设置 `value` 或调用 `clear()` 不派发伪造的用户 `input` 或 `character-select` 事件。

首个版本不承诺原生表单关联行为；宿主通过 `value`、`valid` 和事件集成。

### 8.3 事件

用户提交一次非输入法组合中的文字变化后，组件派发可冒泡且可穿过 Shadow DOM 的标准 `input` 事件。

用户明确选择候选后，组件：

1. 将 `value` 写为正式中文名。
2. 更新 `valid` 和 `selectedCharacter`。
3. 关闭候选列表。
4. 派发一次可冒泡、`composed: true` 的 `character-select` 事件。

事件详情：

```js
{
  id: "prts:352",
  name: "忍冬",
  avatarUrl: "https://...",
  matchedBy: "alias",
  matchedText: "铃兰妈"
}
```

`matchedBy` 使用以下稳定值之一：

- `name`
- `name-pinyin`
- `name-pinyin-alt`
- `name-initials`
- `name-initials-alt`
- `alias`
- `alias-pinyin`
- `alias-pinyin-alt`
- `alias-initials`
- `alias-initials-alt`

用户直接完整输入正式名时，`valid` 为 `true` 且 `selectedCharacter` 可读，但组件不伪造一次 `character-select` 点击事件。

## 9. 视觉与样式隔离

组件使用 Shadow DOM。候选项只显示：

- 头像。
- 正式中文名。

不显示职业、星级、命中原因或其他元数据。

宿主通过以下 CSS 变量调整外观：

| CSS 变量 | 语义 |
| --- | --- |
| `--akni-width` | 组件宽度 |
| `--akni-font-family` | 字体族 |
| `--akni-font-size` | 基础字号 |
| `--akni-text-color` | 文本颜色 |
| `--akni-background` | 输入框与列表背景 |
| `--akni-border-color` | 边框颜色 |
| `--akni-accent-color` | 高亮与焦点颜色 |
| `--akni-radius` | 圆角 |
| `--akni-input-height` | 输入框高度 |
| `--akni-option-height` | 候选项最小高度 |
| `--akni-list-max-height` | 候选列表最大高度 |
| `--akni-z-index` | 候选层级 |

默认主题保持中性紧凑，不强制模拟明日方舟视觉风格。

## 10. 交互与无障碍

状态行为：

- 空输入不显示候选列表。
- 有输入时显示最多 `maxResults` 个候选。
- 无结果时保留自由文本，显示“未找到干员”，并令 `valid=false`。
- 失焦关闭候选列表，但不清空文字。
- 选中后再次编辑会清除旧选择，并按当前文字重新计算状态。

输入方式：

- `ArrowUp`、`ArrowDown` 移动当前候选。
- `Enter` 选择当前候选。
- `Escape` 关闭列表并保留文字。
- 鼠标和触摸可以直接选择。
- 输入法组合期间不反复执行搜索，在 `compositionend` 后统一更新。

无障碍：

- 使用 `combobox`、`listbox` 和 `option` 对应的 ARIA 语义。
- 暴露展开状态、当前高亮项和候选数量。
- 保持清晰的键盘焦点样式。
- 触摸目标尺寸适合常见手机页面。

## 11. 头像加载

角色快照只保存 PRTS 头像 URL，不嵌入头像文件。

加载规则：

- 页面加载时不预取全部头像。
- 每轮搜索只为当前实际展示的最多 `maxResults` 个候选创建头像加载。
- 默认 `maxResults=8`，宿主修改后，候选数量和该轮头像加载上限同步变化。
- 候选文字立即显示，不等待头像。
- 头像加载失败时隐藏头像，候选项自动收紧为纯名字。
- 浏览器负责复用 HTTP 缓存。

快速连续输入时，上一轮已经发出的图片请求可能无法可靠撤回。本规格约束每轮新渲染的候选数量，不承诺所有历史请求的全局并发永远不超过 `maxResults`。

## 12. 数据更新工具

主要命令：

```bash
npm run update-data
npm run check-data
```

`update-data` 执行抓取、关联、拼音生成、覆盖合并、差异比较、校验和原子写入。`check-data` 只校验当前快照，不修改文件。

更新工具应具备：

- 针对两个来源的独立适配器。
- 本地缓存、礼貌的请求间隔、有限重试和退避。
- 清楚标识来源与阶段的错误信息。
- 固定网页样本，便于在站点改版后修复解析器。
- 机器可读的生成数据和便于人类审阅的控制台差异报告。
- 生成文件头部的“不要手工编辑”说明。

更新报告至少列出：

- 新增干员。
- 移除干员。
- 名称变化。
- 新增或移除的别号。
- 同一别号对应多个干员。
- 萌娘百科条目或“别号”缺失。
- 拼音覆盖中已失效或找不到目标的项目。

硬失败条件：

- PRTS 请求失败或解析结果为空。
- 稳定 ID 或正式名缺失、重复。
- 干员数量出现无法解释的剧烈变化。
- 生成数据不符合 schema。
- 生成过程只完成一部分。

软警告条件：

- 萌娘百科条目不存在、消歧义无法确认或没有“别号”。
- 同一别号映射到多个干员。
- 单个头像 URL 无法在更新检查中确认。

只有全部硬校验通过后才原子替换旧快照。任何失败都必须保留最后一次有效数据，不得静默输出降级快照。

## 13. 测试策略

### 13.1 搜索单元测试

- `ll`、`linglan`、`铃`能匹配铃兰。
- `铃兰妈`、`linglanma`、`llm`能通过别号匹配忍冬。
- `chongyue`、`zhongyue`、`cy`、`zy`能匹配重岳，主读音命中优先。
- 正式名首字母命中高于别号首字母命中。
- 合成的一对多别号样本会返回全部对应干员。
- 大小写、空格、全角字符和约定分隔符规范化一致。
- 精确、前缀、包含及稳定同分排序符合规格。

### 13.2 组件测试

- 自由文本保留且未知名字为 `valid=false`。
- 直接输入完整正式名时为 `valid=true`。
- 选择候选后只派发一次 `character-select`。
- 选择后继续编辑会清除旧状态。
- 键盘、鼠标、触摸和输入法组合行为正确。
- 头像失败时仍可选择角色。
- 每轮只为最多 `maxResults` 个候选创建头像元素或设置头像 URL。
- 多实例互不影响。
- 宿主全局 CSS 不污染 Shadow DOM。

### 13.3 更新工具测试

普通测试只使用固定的 PRTS 与萌娘百科网页/API 样本，不依赖实时网络。覆盖：

- 正常解析。
- 页面缺失和无“别号”。
- 重定向与无法确认的消歧义。
- 重复 ID、空结果和来源结构变化。
- 请求失败。
- 原子写入失败保护。
- 人工主读音与备用读音在更新后保留。
- 差异报告完整。

另提供显式的手动联网验证流程，用于确认真实站点当前结构。它不进入普通 CI，避免网络波动造成假失败。

### 13.4 浏览器端到端测试

- Chromium、Firefox 和 WebKit。
- 桌面与手机尺寸。
- 无框架纯 HTML 宿主页。
- 键盘焦点、ARIA 状态、候选层级和触摸区域。
- 慢速头像与断网头像场景。
- 搜索与选择不等待网络。
- 控制台无未处理异常。

## 14. 验收标准

完成实现必须同时满足：

1. 一条 `<script>` 和一个自定义标签即可运行。
2. 不需要宿主安装运行时依赖。
3. 正式名、拼音全拼、拼音首字母、别号及其拼音均可按规则搜索。
4. 多音字主读音和合理备用读音均可命中。
5. 排序稳定，正式名首字母高于别号首字母。
6. 自由文本、`valid`、`selectedCharacter` 和选择事件符合接口契约。
7. 候选只显示头像与正式中文名。
8. 每轮头像加载数量跟随 `maxResults`。
9. 头像失败或断网不影响名字搜索与选择。
10. `npm run update-data` 能安全生成差异并更新快照。
11. 数据异常不会覆盖最后一次有效快照。
12. 规定的单元、组件、更新工具和多浏览器测试通过。

## 15. 建议的模块边界

实现应保持以下职责分离，具体文件名可在实施计划中细化：

- PRTS 来源适配器：只负责主干员数据。
- 萌娘百科来源适配器：只负责角色条目“别号”。
- 文本与拼音规范化器：只负责生成搜索键和读音变体。
- 数据合并与校验器：只负责关联、差异和完整性规则。
- 搜索核心：只接收规范化数据并返回稳定排序结果。
- Web Component：只负责状态、渲染、交互和事件。
- 构建入口：只负责将数据和运行时代码产出为发布 JS。
